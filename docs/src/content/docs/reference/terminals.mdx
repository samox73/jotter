jOtter needs a terminal with an image protocol: kitty graphics, sixel or the iTerm2 protocol. In a terminal without one it prints an error and doesn't start, unless plots are drawn as [Braille text](/jotter/guides/outputs/#braille-plots) with `--braille`. What differs between the supported terminals is the protocol and whether modified keys like <kbd>Shift</kbd>+<kbd>Enter</kbd> work. [Terminal setup](/jotter/getting-started/terminal-setup/) explains both.

| Terminal | Images | <kbd>Shift</kbd>+<kbd>Enter</kbd> | Notes |
| --- | --- | --- | --- |
| [kitty](https://sw.kovidgoyal.net/kitty/) | kitty graphics | yes | Recommended. |
| [Ghostty](https://ghostty.org) | kitty graphics | yes | |
| [foot](https://codeberg.org/dnkl/foot) | sixel | yes | |
| [WezTerm](https://wezfurlong.org/wezterm/) | iTerm2 protocol | with `enable_kitty_keyboard = true` | |
| tmux (inside kitty) | the outer terminal's, with `allow-passthrough on` | no | tmux doesn't forward the keyboard protocol. |
| [xterm](https://invisible-island.net/xterm/) | sixel as a VT340 | no | `xterm -ti vt340` (or `xterm*decTerminalID: vt340`); not supported otherwise. |

These results come from jOtter's own detection in each terminal (kitty 0.49, Ghostty 1.3, foot 1.27, WezTerm 2026-03, xterm 411, tmux 3.6), with default settings. The docs' recording rig checks them again whenever it runs. Run jOtter with `--log` to see what it detects in yours: the log's `terminal:` line names the image protocol, the cell size and the keyboard protocol.

**<kbd>Shift</kbd>+<kbd>Enter</kbd>: no** means the terminal doesn't use the kitty keyboard protocol. Use <kbd>r</kbd> (run and advance) and <kbd>Space</kbd> (run in place) instead.

## Not supported

These terminals have no image protocol jOtter can use, so it doesn't start in them:

- macOS Terminal.app
- [Alacritty](https://alacritty.org)
- [GNOME Terminal](https://gitlab.gnome.org/GNOME/gnome-terminal) (VTE 0.84)
- [Konsole](https://konsole.kde.org): it has sixel and part of the kitty protocol, but both are incomplete in ways jOtter's image library can't use.

`jotter --braille` starts there with plots drawn as Braille text and math as Unicode approximations; `jotter --no-images` starts without plots and rendered math. Neither combination is part of the tested set.

Using a terminal not listed here? Please [report how it works](https://github.com/samox73/jotter/issues/new), with the `terminal:` line from a `--log` run, so this table can include it.
